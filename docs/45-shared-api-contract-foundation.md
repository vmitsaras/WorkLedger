# Shared API Contract Foundation

`WL-304` establishes the transport contract used by later WorkLedger feature routes. It does not
add product endpoints or expose the generated OpenAPI document publicly.

## Contract ownership

`packages/contracts/src/api.ts` is the shared runtime and type source for:

- the stable API error-code catalog;
- bounded field-error codes and canonical safe messages;
- server-generated request identifiers;
- success/error metadata and envelopes; and
- flat, bounded recovery context suitable for purpose-specific conflict handling.

Schemas use strict Zod objects. Unknown fields fail rather than being silently stripped. Transport
types are inferred from schemas, so feature work must not add duplicate request/response
interfaces.

## Fastify boundary

`apps/api/src/http/foundation.ts` installs the Zod validator and response serializer, registers
OpenAPI 3.1 generation before routes, creates UUID request identifiers, and owns the final error
boundary. The generated OpenAPI document is inspected in tests; `WL-308` decides public exposure
and typed-client generation.

Every response receives an `X-Request-Id` generated by the server. An incoming `X-Request-Id` is
ignored. Normal WorkLedger success envelopes repeat the identifier in `meta.requestId`; every error
repeats it in `error.requestId`. Retry-sensitive outcomes additionally carry
`meta.idempotentReplay` without making transport request IDs part of semantic replay equality.

Swagger registration must complete before feature routes are declared. `createApiServer` therefore
registers the current health/authentication routes in Fastify's post-registration callback; future
route registrars must preserve that ordering.

## Error mapping

The transport distinction is fixed:

- malformed JSON: `400 MALFORMED_REQUEST`;
- syntactically valid schema failure: `422 VALIDATION_FAILED`;
- unknown route: `404 ROUTE_NOT_FOUND`;
- unsupported media type: `415 UNSUPPORTED_MEDIA_TYPE`;
- oversized body: `413 REQUEST_TOO_LARGE`;
- explicit safe application errors: their declared stable code/status; and
- response serialization or unknown internal failure: `500 INTERNAL_ERROR`.

Validation mapping never returns Zod/Fastify messages, request values, or unknown field names.
Known schema paths map to canonical field codes/messages; all unknown properties collapse to the
root `$` path. Error responses are `private, no-store`.

`WorkLedgerApiError` accepts only the bounded safe error structures defined by contracts. The final
sender reparses every candidate envelope. If a supposedly safe context is invalid or oversized, it
falls back to a generic `500 INTERNAL_ERROR` rather than throwing from the error handler.

## Evidence

Contract tests prove strict success/error envelopes and reject nested, oversized recovery context.
API integration tests cover:

- `422` type and unknown-field failures without input echo;
- separate malformed-JSON and route-not-found responses;
- safe application conflicts and idempotent-replay metadata;
- unknown exceptions and response-serialization failure redaction;
- invalid safe-context fallback;
- server-owned fresh request IDs; and
- stable OpenAPI 3.1 generation without a public specification endpoint.

No UI changed. The later web form/error work must turn stable field codes into clear prose, link the
error summary to controls, focus the summary heading, and announce only meaningful results as
defined in `docs/05-ux-accessibility.md`.
